# Domain Docs

This is a single-context repo.

Before exploring, engineering skills should read these when present:

- `CONTEXT.md` at the repo root
- `docs/adr/` for architectural decisions touching the area being changed

If these files do not exist, proceed silently. Do not suggest creating them upfront; producer skills such as `grill-with-docs` create them lazily when terms or decisions are resolved.

Use the domain vocabulary from `CONTEXT.md` in issue titles, refactor proposals, hypotheses, and test names. If a needed concept is missing, note it as a possible documentation gap.

If output contradicts an ADR, surface the conflict explicitly.
